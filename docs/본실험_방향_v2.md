# 본실험 방향 v2 — DSR 골격으로 재배치

- 작성일: 2026-11-12
- 이전 판: `docs/본실험_방향_v1.md` (파일럿 A1 직후, 진단 중심)
- 참고 구조: "When AI Oversees AI" (LLM 기반 CRM 감독 아키텍처 원고) — Peffers(2007) DSRM + Hevner(2007) 3주기 + Larsen(2025) criterion/causal/context 주장 + Gregor(2020) 설계 원칙
- 결론 먼저: **연구 유형을 "진단"에서 "설계(DSR)"로 바꾼다.** 파일럿 결과는 문제 확인 근거로 내리고, 그 위에 아티팩트(검증기 내장 트윈 구축 절차)와 기준선 대비 평가, 설계 원칙을 얹는다. 주제 자체는 바뀌지 않는다.

## 1. 문제와 긴장 (Problem Identification)

공개 인터뷰 자료만으로 실존 인물의 트윈을 만들 때 생기는 세 가지 긴장. 파일럿 수치는 `발표_파일럿_실험과정_정리.html` §7.

| | 긴장 | 파일럿 근거 | 근거 강도 |
|---|---|---|---|
| **T1** | **개인화 ↔ 충실도**: 페르소나 정보를 더 넣을수록 본인에 가까워져야 하는데, 오히려 요약 전형으로 쏠리고 부정 발화가 온건해진다 | stance G0 56.7 → G2 54.1(개선 없음). 부정 문항 valence gap G0 +0.76 → G2 +1.44. 거리 G2–G1 0.865 < G2–본인 0.952 | 방향은 일관. 부정 문항 n=9, 자기 채점 → **게이트 대상** |
| **T2** | **포괄 ↔ 정확**: 모든 질문에 답하게 하면 자료에 없는 것을 지어내고, 답을 아끼면 쓸모가 줄어든다 | 근거 유형: 본인 일화 44% vs G2 혼합 74%. 기술층·가치 충돌 문항에서 페르소나 효과 없음(충돌 39.8 → 40.3) | 환각 여부 미검증(0-5) |
| **T3** | **검증 비용 ↔ 확장성**: 본인·코더에게 매번 확인받을 수 없다. 자동 검증이 필요하지만 같은 모델이 채점하면 자기 채점 문제가 남는다 | 파일럿에 코더·본인 응답 없음. 생성·판정 모두 DeepSeek | 구조적 제약 |

**연구 질문(가안)**: 공개 인터뷰 자료만으로 만든 인물 트윈에서, 본인 확인 없이도 전형 쏠림과 긍정화를 줄이는 구축·검증 절차를 어떻게 설계할 것인가?

### 사용 맥락 (relevance) — 확정 필요
- 가안: 공인·크리에이터의 공개 자료로 만든 트윈을 **마케팅 조사·콘텐츠 사전 점검**(예: 브랜드 협업 제안에 대한 반응 예측)에 쓰려는 연구자·실무자. 이 맥락에서는 "싫다·안 한다"를 "좋다"로 바꿔 답하는 오류가 가장 비싸다 → T1이 실무 문제가 된다.
- CRM 원고의 파트너 기업·실무자 인터뷰에 해당하는 것이 없다. 최소한 사용 시나리오 1개를 정하고, 가능하면 실무자 2~3명의 짧은 의견을 받는다.

## 2. 설계·검증 과정 (DSRM 대응표)

| DSRM 단계 | 설계 의도 | 이 연구에서 |
|---|---|---|
| 문제 확인 | 인터뷰 기반 트윈의 왜곡 | T1~T3 (파일럿 A1 + 게이트 0-1~0-6) |
| 해결 목표 | 설계 목표 DO1~DO4 | §3 |
| 설계·개발 | 검증기 내장 트윈 구축 절차 | 생성기 + 균형 발췌 + 충실도 검증기(재생성 루프) + 보류 규칙 (§4) |
| 시연 | 한 인물에 구현, 부품별 점검 | 노라(P01) Train 381로 구현. 검증기 판정을 사람 채점 100쌍과 대조 |
| 평가 | criterion / causal / context 주장 | Holdout 본인 답 기준 5조건 비교 (§5) |
| 지식 기여 | 설계 원칙 DP1~DP4 | §6 |
| 소통 | 논문, 저장소 | 가명 처리 데이터·코드 공개 범위는 별도 결정 |

## 3. 설계 근거 (긴장 → 목표 → 구성요소)

| 긴장 | 설계 목표 | 구성요소 | 검증 기준 |
|---|---|---|---|
| T1 | **DO1** 발췌가 인물의 "따뜻한 면"만 전달하지 않게 한다 | **C1 균형 발췌**: 주제 유사 10 + 부정·단호 발화 5 + 말투 특징 발화 5 | 부정 문항 valence gap, 긍정 문항 비악화 |
| T1·T3 | **DO2** 생성과 충실도 검증을 분리한다 | **C2 충실도 검증기**: 생성 모델과 다른 패밀리의 모델이 답을 Train 자료와 대조해 통과·반려. 반려 시 사유를 붙여 재생성(최대 2회) | gap 추가 감소, stance 일치, 사람 채점과의 일치 |
| T2 | **DO3** 자료로 뒷받침되지 않는 답은 내보내지 않는다 | **C3 보류 규칙**: 재생성 한도 내 통과 못 하거나 관련 Train 발화가 없으면 "자료로는 답하기 어렵다"로 보류 | Risk–Coverage 곡선, 지어낸 일화 비율 |
| T1·T2 | **DO4** 절차가 통하는 범위를 밝힌다 | **C4 적용 경계**: 문항 층(가치관·일화·채널·기술), 극성, 가치 충돌 여부별 효과 | 층별·극성별 효과 차이 |

### 설계 근거를 대는 보조 분석
- **G1 분해**(v1 4-2): 요약을 생애만 / 가치관만 / 말투만으로 나눠 어느 문단이 긍정화를 만드는지 본다. C1에서 "부정·말투 발화를 따로 보장해야 하는 이유"의 근거.
- **전체 삽입 상한**(0-6): Train 381개 전부 삽입. 올라가면 "검색의 한계" → C1의 근거. 안 올라가면 "자료의 한계" → C3(보류)의 근거.

## 4. 아티팩트: 검증기 내장 트윈 구축 절차

```
질문 ─▶ [C1 균형 발췌] ─▶ [생성기: 요약 + 발췌 20] ─▶ 답 초안
                                                  │
                              [C2 충실도 검증기] ◀─┘   (다른 패밀리 모델, Train 자료만 참조)
                               ├─ 통과 ─────────────▶ 답 출력
                               ├─ 반려(사유) ─▶ 재생성 (최대 2회)
                               └─ 한도 초과·근거 없음 ─▶ [C3 보류]
```

### C2 검증기가 보는 세 가지 (본인 답 없이 Train만으로 판단)
| 점검 | 질문 | 반려 예 |
|---|---|---|
| 극성 | 답의 태도가 관련 Train 발화들의 태도 분포 안에 있는가 | 관련 발화는 대부분 비판적인데 답은 호의적 |
| 근거 | 답에 나온 일화·사실이 Train 또는 요약에 있는가 | 자료에 없는 경험담 |
| 말투 | 단호함·직설 정도가 발췌와 비슷한가 | 발췌는 단정형인데 답은 돌려 말함 |

- 검증기는 Holdout 본인 답을 **보지 않는다**(실제 배치 상황과 같게). Holdout은 평가에만 쓴다.
- 검증기 기준은 파일럿 출력 일부로 보정(프롬프트 조정)하고, 보정에 쓴 문항은 평가에서 뺀다.
- 구현: 기존 `retrieve.py`에 층화 옵션, `run.py`에 검증·재생성 루프, `prompts/reviewer.txt` 신규.

## 5. 평가 (Larsen 틀)

### 5-1. 조건
| 코드 | 구성 | 역할 |
|---|---|---|
| B0 | 빈 페르소나(=G0) | 바닥 기준 |
| **B1** | 요약 + 유사도 발췌 20(=G2) | **기준선**(통상 방식) |
| A-ret | B1의 발췌만 균형 발췌로 교체 | C1 단독 |
| A-rev | B1 + 검증기·재생성 | C2 단독 |
| **A-full** | 균형 발췌 + 검증기 + 보류 | 아티팩트 전체 |
| (참고) | Train 전체 삽입 | 자료 상한 |

### 5-2. 주장·가설·방법
| 목표 | 주장 | 가설 | 방법 |
|---|---|---|---|
| 전체 | **Criterion 1**: 아티팩트가 기준선보다 본인에 가깝다 | **H1** A-full은 B1보다 부정 문항 valence gap이 작고 stance 일치가 높다. 긍정 문항에서는 나빠지지 않는다 | Holdout 문항 단위 대응 비교(문항 군집 부트스트랩) |
| DO1 | **Causal 1**: 발췌 구성이 효과를 낸다 | **H2** A-ret의 gap < B1 | 같은 방법 |
| DO2 | **Causal 2**: 독립 검증이 추가 효과를 낸다 | **H3** A-rev의 gap < B1, A-full < A-ret | 같은 방법 + 검증기 판정과 사람 채점 일치도(κ) |
| DO3 | **Criterion 2**: 보류가 오류를 골라낸다 | **H4** 검증기 점수로 보류할 때의 Risk–Coverage 곡선이 무작위 보류보다 낫다. 답한 문항의 지어낸 일화 비율이 B1보다 낮다 | Risk–Coverage, 일화 대조 수작업 |
| DO4 | **Context 1**: 효과는 문항 성격에 따라 다르다 | **H5** 개선은 부정·가치 충돌 문항에서 크고, 일화·채널층과 긍정 문항에서는 작다 | 층·극성별 조절 분석 |
| DO4 | **Context 2**(선택): 다른 인물에서도 통한다 | H6 두 번째 인물에서 H1 방향 재현 | 인물 1명 추가, 축소 규모 |

### 5-3. 측정
- **주 지표**: valence gap(부정 문항), stance 일치 — 판정은 생성 모델과 **다른 패밀리**, 눈가림, T=0
- **보조**: ground·voice, sim_emb(e5), 지어낸 일화 비율, coverage(답한 비율), 재생성 횟수(비용)
- **사람 검증**: 코더 2인 100쌍(κ/ICC) — 판정 모델과 검증기 둘 다 여기에 대조
- **프레임·CoT·온도**(v1 4-1, 4-4): A-full과 B1에서만, 부록

### 5-4. 규모 (가안)
- 문항: 부정 30 + 대조 긍정 30 = 60 (검증기 보정용 문항 제외)
- 생성: 60 × 5조건 × (T=1 5회 + T=0) = 1,800회, 검증·재생성 약 2,000회, 판정 1,800회
- 전체 삽입 참고 조건은 0-6에서 이미 측정

## 6. 설계 원칙 (가안 — 결과에 따라 수정)

| | 원칙 | 대응 |
|---|---|---|
| DP1 | 인물 트윈에서는 답을 만드는 일과 충실도를 검증하는 일을 분리하고, 검증은 다른 모델이 원자료에 대조해 수행한다 | DO2 |
| DP2 | 발췌는 주제 유사도만으로 고르지 않고, 인물의 부정·단호 발화와 말투 발화를 일정 몫 보장한다 | DO1 |
| DP3 | 원자료로 뒷받침되지 않는 질문에는 답하지 않게 하고, 보류 비율을 함께 보고한다 | DO3 |
| DP4 | 트윈은 자료가 닿는 문항 유형에만 쓰고, 가치 충돌·자료 밖 주제에는 조건부로 쓴다 | DO4 |

## 7. 게이트와 분기 (v1 §3 유지)

게이트 작업 0-1 ~ 0-6은 v1 §3 표 그대로. 결과에 따라 T1의 내용과 아티팩트 무게중심만 바뀌고 골격은 같다.

| 게이트 결과 | T1의 내용 | 무게중심 |
|---|---|---|
| 다른 패밀리 판정·부정 문항 30+에서 gap ≥ +0.8이고 G2 > G0 | 긍정 쏠림 | C1 균형 발췌 + C2 극성 점검 |
| gap이 사라지거나 조건 차이 없음 | 전형 의존(요약에 머묾) | C3 보류 + C2 근거 점검, 주 지표를 Risk–Coverage로 |
| 전체 삽입(0-6)에서 크게 개선 | 검색의 한계 | C1을 본체로, 전체 삽입을 비용 기준선으로 추가 |

## 9. 약점과 대응

| 약점 | 대응 |
|---|---|
| 인물 1명 | 주장을 "한 인물에서의 시연과 평가"로 한정. 여력 있으면 H6(인물 1명 추가) |
| 행동 결과 변수 없음(CRM 원고는 실제 클릭) | 본인의 이후 인터뷰 답(Holdout)을 실제 행동의 대리로 명시. 사람 채점으로 판정 모델 보정 |
| 본인 답의 변동(Retest 천장 stance 56) | 모든 지표를 천장 대비로 보고. 개선 여지가 작다는 점을 한계로 명시 |
| 검증기도 LLM | 다른 패밀리 사용 + 사람 채점 대조. 검증기가 Holdout을 보지 않게 분리 |
| 사용 맥락·실무자 근거 없음 | 시나리오 1개 확정, 가능하면 짧은 실무자 의견 수집 |
| 부정 문항이 30개에 못 미칠 수 있음 | 0-3 결과가 20개 미만이면 valence ≤ 0 "단호" 문항까지 넓히고 기준을 문서화 |

## 10. 논문 목차 (가안)

1. 서론 — 인물 트윈의 쓰임, T1~T3, 연구 질문, 기여
2. 관련 연구 — LLM 트윈의 왜곡(Funhouse Mirrors, Twin-2K-500, Fragile Preferences 등), 긍정·바람직성 편향, 검색 증강과 검증기 구조
