- 작성일: 2026-11-12
- 이전 판: `본실험_방향_v1.md`(진단 중심), `본실험_방향_v2.md`(CRM 원고 틀: 긴장 → 설계 목표 → 가설)

## 1. 문제 (서론용 — v2 §1 유지)

- **T1 개인화 ↔ 충실도**: 페르소나 정보를 더 넣어도 본인에 가까워지지 않고, 부정 문항에서 긍정 쪽으로 더 쏠린다(valence gap G0 +0.76 → G2 +1.44, 부정 문항 n=9).
- **T2 포괄 ↔ 정확**: 자료에 없는 질문에도 답하며 일화를 섞는다(본인 일화 44% vs G2 혼합 74%).
- **T3 검증 비용 ↔ 확장성**: 본인·코더 확인 없이 트윈 답의 충실도를 알 방법이 없다.

**Etudo & Yoon과의 대응**: 그 논문은 "손 라벨 없이 급진 게시물을 이념별로 분류"가 빈칸이었다. 우리 빈칸은 "**본인 확인 없이 트윈 답이 본인 입장과 맞는지 판별**"이다(T3). T1·T2는 그 판별이 왜 필요한지의 근거.

사용 맥락(가안, 확정 필요): 공인·크리에이터의 공개 자료로 만든 트윈을 마케팅 조사·콘텐츠 사전 점검에 쓰는 상황. 트윈 답을 그대로 믿을지, 버릴지, 본인에게 물어야 할지를 가려 주는 도구.

## 3. 근거 이론 (kernel theory) — 확정 필요

Etudo & Yoon은 집단행동 프레이밍 이론에서 온톨로지 클래스(진단·예후·동기 프레임)를 끌어온다. 우리도 "왜 극성·근거 유형·말투인가"를 이론으로 대야 한다. 파일럿의 태그는 조작적 정의일 뿐이다.

| 온톨로지 요소 | 후보 이론 | 끌어올 것 | 상태 |
|---|---|---|---|
| 대상–극성–강도 | 태도 이론(태도 = 대상에 대한 평가) | 입장을 "대상 + 평가 방향 + 강도"로 표현하는 근거 | 문헌 확인 필요 |
| 근거 유형(일화·원칙·사실) | 논증 모형(주장–근거–보장) | 입장과 그 뒷받침을 분리하는 근거 | 문헌 확인 필요 |
| 말투(단정·완곡), 긍정 쏠림 | 자기 제시·인상 관리, 사회적 바람직성 | 트윈이 온건해지는 현상의 해석 틀 | 문헌 확인 필요 |
| 불충실 유형 | 수업 논문의 왜곡 분류(Funhouse Mirrors의 다섯 왜곡, Twin-2K-500, Fragile Preferences) | 탐지 대상(무엇을 불충실이라 부르나)의 정의 | 프로젝트 문서에 요약 있음 |

할 일: 후보별 대표 문헌 2~3편을 확인해 하나의 중심 이론을 고른다. 중심 이론이 정해지지 않으면 RQ1이 "태그 목록"에 머문다.

개발 방법은 Etudo & Yoon과 같이 온톨로지 개발 방법론(METHONTOLOGY: 명세 → 지식 획득 → 개념화 → 구현 → 평가)을 따르고, 지식 획득은 Train 발화의 주제 코딩으로 한다.

## 4. 아티팩트

```
[Train 인터뷰 381] ─▶ (2) 입장 추출기 SES ─▶ (1) 인물 입장 온톨로지 PSO (채워진 사본)
                                                        │
질문 ─▶ 트윈(요약+발췌) ─▶ 답 ─▶ SES로 답의 입장 추출 ─▶ (3) 충실도 검증기 FAS
                                                        │   답의 입장 vs 본인 입장 → 충실도 프로필
                                                        ├─ 충실 ─▶ 출력
                                                        └─ 불충실 ─▶ (응용) 재생성 / 보류
```

### 4-1. 인물 입장 온톨로지 (PSO) — RQ1
이전 설계안의 9개 개념을 측정에 쓰이는 것만 남겨 줄인다.

| 클래스 | 설명 | 속성 | 이전 설계안 대응 |
|---|---|---|---|
| Person | 재현 대상 인물(가명) | person_id | Person |
| Statement | 한 번의 답변 | text, source, time | Statement + Evidence + Source + Time |
| Topic | 입장의 대상 | topic_name, 상위 주제 | Topic |
| Stance | 대상에 대한 평가 | polarity(−2~+2), intensity | Attitude |
| Ground | 입장의 뒷받침 | type(일화·원칙·사실·혼합), 요지 | (신규 — 파일럿 태그) |
| Voice | 말하는 방식 | 단정·완곡 | (신규 — 파일럿 태그) |

관계: `aboutTopic`, `expressesStance`, `groundedIn`, `spokenWith`, `revises`(같은 주제에서 시점에 따라 입장이 바뀜 — Retest 14쌍에서 확인된 현상).

- 뺀 것: Attribute(생애 속성 — 요약문이 담당), 별도 Evidence 노드.
- 구현: JSON-LD 또는 단순 트리플 테이블. OWL 추론은 쓰지 않는다(필요성 없음).

### 4-2. 입장 추출기 (SES) — RQ2
- 입력: 질문+답 한 쌍. 출력: (Topic, Stance, Ground, Voice) 트리플 묶음.
- 구현: 스키마로 출력 형식을 묶은 LLM 추출(기존 `tag_items.py` 확장). Topic은 Train에서 만든 주제 목록에 대응시키고, 없으면 신규 주제로 표시.
- Train 381개에 적용해 PSO를 채우고, 같은 추출기를 트윈 답에도 적용한다(Etudo & Yoon에서 같은 추출 과정을 이념 문서와 검사 대상 문서 양쪽에 쓰는 것과 같은 구조).

### 4-3. 충실도 검증기 (FAS) — RQ3
트윈 답 하나에 대해 **충실도 프로필**(벡터)을 계산한다. Etudo & Yoon의 공명 프로필에 해당.

| 요소 | 계산 | 뜻 |
|---|---|---|
| 극성 편차 | 답의 polarity − 같은 Topic 본인 발화들의 polarity 분포(평균·범위) | 본인보다 호의적·비판적인가 |
| 근거 지지 | 답의 일화·사실이 PSO의 Ground 요지와 대응되는 비율 | 자료에 없는 것을 지어냈나 |
| 말투 편차 | 답의 Voice vs 같은 Topic 본인 Voice | 돌려 말하나 |
| 자료 범위 | 같은 Topic(및 상위 주제)의 본인 발화 수 | 답할 근거가 있나 |
| 입장 변동 | 해당 Topic에 `revises` 관계가 있는가 | 본인도 흔들린 주제인가 |

- 판정: 프로필 → 규칙 기반 점수(가중합 + 기준값), 그리고 프로필을 특징으로 쓰는 단순 분류기. 둘 다 보고.
- 검증기는 Holdout 본인 답을 보지 않는다. Holdout은 평가용 라벨에만 쓴다.

### 4-4. 응용 (탐지 결과의 사용)
- **재생성**: 불충실 판정 시 편차 사유를 붙여 다시 생성(최대 2회).
- **보류**: 자료 범위가 0이거나 재생성 후에도 불충실이면 답을 내지 않는다.
- **층화 발췌**: PSO의 polarity 태그로 부정·단호 발화를 일정 몫 보장(v2의 C1).

## 5. 평가 (부품별 — Etudo & Yoon 구성)

### E1. 온톨로지 평가 (RQ1)
| 방법 | 내용 | 기준 |
|---|---|---|
| 역량 질문 | "이 인물은 X에 대해 어떤 입장인가", "그 근거는 일화인가 원칙인가", "입장이 바뀐 주제는" 등 10~15개를 질의로 답할 수 있는가 | 전부 답 가능 |
| 표현 범위 | Train 381개 중 스키마로 손실 없이 표현되는 비율 | 무작위 50개 수작업 확인 |
| 전문가 검토 | 지도교수·동료 연구자 1~2명에게 클래스·관계 타당성 의견 | 수정 반영 기록 |

### E2. 추출 평가 (RQ2)
- 정답: **손으로 검수한 발화 150개**(Train 100 + 트윈 답 50). 미뤄 둔 태그 검수가 여기서 필수가 된다.
- 지표: Topic 대응 정확도, polarity 일치(±1 허용 포함), Ground·Voice의 정밀도·재현율·F1.
- 비교: (a) 형식 제약 없는 단일 프롬프트(파일럿 방식) / (b) 스키마 제약 추출 / (c) 추출 모델 2종.

### E3. 탐지 평가 (RQ3 — 주 결과)
- 대상: 트윈 답(파일럿 A1 출력 1,200개 + 본실험 생성분).
- 라벨: Holdout 본인 답과의 불일치를 자동 라벨로 사용(다른 패밀리 판정 모델의 stance가 기준값 미만이거나 valence 차이 ≥ 2). 사람 채점 100쌍으로 라벨 품질 확인. → "손 라벨 없이" 주장의 근거이자 약한 고리.
- 비교 기준:

| 코드 | 검증 방식 |
|---|---|
| D0 | 무작위 / 전부 충실로 판정 |
| D1 | 생성 모델의 자기 확신 점수 |
| D2 | 검색 유사도(질문과 가장 가까운 Train 발췌와의 거리) |
| **D3** | **온톨로지 없는 LLM 검증기** — 발췌 원문 20개를 읽고 충실 여부 판단 (v2의 검증기) |
| **D4** | **FAS** — 온톨로지 기반 충실도 프로필 |

- 지표: 정밀도·재현율·F1, AUROC, Risk–Coverage 곡선(검증 점수 순으로 보류할 때 남은 답의 오류율).
- 제거 실험: 프로필에서 극성·근거·말투·범위·변동 요소를 하나씩 빼고 성능 변화.
- 층별: 가치관·일화·채널·기술층, 부정/긍정 문항별 탐지 성능.

### E4. 응용 시연 (트윈 개선)
- 조건 3개: B1(요약 + 유사도 발췌, 파일럿 G2) / A-ret(층화 발췌) / A-full(층화 발췌 + FAS 재생성·보류).
- 문항: 부정 30 + 긍정 30, T=1 5회 + T=0.
- 지표: 부정 문항 valence gap, stance 일치, 지어낸 일화 비율, 답한 비율.
- 가설 검정이 아니라 "탐지가 쓸모 있다"는 시연으로 보고.

### E5. 일반성
- 두 번째 인물(공개 인터뷰가 충분한 인물 1명)에 PSO 스키마를 그대로 적용해 E2·E3를 축소 규모로 반복. 스키마 수정이 얼마나 필요했는지 기록.

## 6. 게이트 (v1 §3의 0-1 ~ 0-6 유지 + 0-7 신규)

| 순서 | 작업 | 통과 기준 | 실패 시 |
|---|---|---|---|
| 0-1~0-6 | v1 §3 그대로(판정 모델 교체, 태그 검수, 부정 문항 확충, e5, 환각 대조, 전체 삽입 상한) | — | T1의 내용이 바뀜(v2 §7 분기표) |
| **0-7** | **온톨로지 유무 소규모 비교**: 기존 A1 출력 중 300개에 D3와 D4(간이판: Train 태그만으로 극성 편차·자료 범위 계산)를 적용해 Holdout 불일치 탐지 AUROC 비교. 생성 호출 없음 | D4가 D3보다 높거나, 비슷하면서 호출 비용이 뚜렷이 낮음 | 온톨로지를 빼고 **v2로 복귀** |
| 0-7b | **자료 범위 곡선**(0-7과 같은 재료): Holdout 문항을 'Train에 같은 주제 발화가 몇 개 있었나'로 나눠 G0·G1·G2 일치도 비교. 설계는 `게이트0-7_온톨로지유무_자료범위_설계.md` | 통과·실패가 아니라 해석용 — 범위가 클수록 G2−G0가 커지면 자료 범위를 적용 경계로 | 평평하면 검색·생성 쪽(0-6)으로 무게 이동 |
| 0-8 | 근거 이론 확정(§3) | 중심 이론 1개 + 클래스별 근거 문헌 | RQ1을 약화해 "측정 스키마"로 표현하고 기여를 RQ3에 집중 |

0-7을 가장 먼저 한다. 비용이 가장 낮고, 이 판 전체의 성립 여부를 가른다.

## 8. 약점과 대응

| 약점 | 대응 |

## 9. 논문 목차 (Etudo & Yoon 구성)

1. 서론 — 인물 트윈의 쓰임, T1~T3, RQ1~3, 기여
2. 문헌 — LLM 트윈의 왜곡, 답변 검증·선택적 응답, 온톨로지 기반 설계 연구
3. 이론적 근거 — 중심 이론과 온톨로지 클래스의 대응
4. 설계 — 전체 구조, PSO, SES, FAS, 연구 틀 그림(RQ – 이론 – 아티팩트 – 평가 대응)
5. 평가 — E1 온톨로지, E2 추출, E3 탐지(비교 기준·제거 실험), E4 응용 시연, E5 두 번째 인물
6. 논의 — 설계 지식(v2의 DP1~DP4를 결과에 맞춰 수정), 이론·실무 기여, 한계
